## What exists
- models/router.py: async complete() over anthropic + ollama. Reasoning is split out
  (Ollama `reasoning` field or inline <think> tags), every call goes to the run log,
  and ModelResponse.cost_usd is set.
- models/pricing.py: Anthropic prices as of 2026-10-16, Haiku long-prompt tier, ollama = 0.
- core/plugin.py: the Plugin protocol (name, modes -> required roles, max_calls, schema, load_tasks,
  validate_lineup, run_task), Session (call limit, cost, run log), Outcome (score 0-1, attempts,
  verdict, fail_reason, error, stop_reason, metrics), PluginError, ModelCallFailed, CallLimitReached.
  core never imports a plugin; plugins/__init__.py is a plain dict PLUGINS + DEFAULT_PLUGIN.
- core/runlog.py: SQLite data/arena.db with runs, calls (full prompt/response/reasoning/error) and
  results (+ score, metrics JSON). code_bounty's schema adds attempts (code + grade per attempt).
- core/lineup.py + config/lineups.yaml: optional plugin: (default code_bounty), mode, roles; a role
  is a model string or {model, think}. extra="forbid" on Lineup and RoleConfig. load_lineups(PLUGINS,
  DEFAULT_PLUGIN) checks mode/roles against the plugin, then plugin.validate_lineup.
- core/taskboard.py: async TaskBoard Protocol plus a SQLite implementation (atomic claim).
- core/orchestrator.py: run_lineup(plugin, lineup, tasks, ...) -> plugin.run_task per task. Board,
  results, Ctrl-C; PluginError aborts the run; an escaped ModelCallFailed = unscored error outcome.
- plugins/code_bounty/plugin.py + loop.py: run_task -> solve_solo() | solve_team(). max_attempts per
  lineup (default 3), CodeBounty.max_calls=20 enforced by Session; grade_reply grades and logs
  attempts. Team loop: planner ->
  coder -> grader; on failure reviewer -> orchestrator (DECISION: RETRY|REPLAN|GIVE_UP,
  unparseable = retry). Every team call is a fresh 1-message conversation (current plan +
  latest attempt only). Replan restarts the coder without the old code. Reviewer and
  orchestrator are skipped after the last attempt and after a reply with no code.
  Worst case 10 calls/problem. Outcome.gave_up marks an orchestrator give-up.
- core/scoreboard.py: every result in every run of one plugin (--plugin, default code_bounty) is one
  trial; score = COALESCE(results.score, results.passed), so pre-plugin rows count the same.
- plugins/code_bounty: grader.py (Docker sandbox, GraderError for infra failures),
  roles.py (solo + team prompts, parse_decision), problems.py (loading + extract_code).
- problems 001-010, each with a reference.py that tests/test_solo.py grades.
- CLI: arena smoke | run --lineup X [--problem 001] [--repeat N] | scoreboard [--since RUN_ID] [--plugin P]
  The scoreboard's "per run" column is the lowest-highest single-run pass rate per lineup, over
  full runs only (runs.problem NULL, not interrupted, finished). runs.problem records --problem.

## Open decisions / known issues
- Local-model wall time includes the cold load on a run's first problem (gpt-oss ~25s).
  An untimed warm-up call was offered; not decided.
- Ollama reasoning_tokens is a character-share estimate; Anthropic reports thinking_tokens exactly.
- think=false can't fully disable gpt-oss thinking.
- Ctrl-C or SIGTERM (to `uv run` or the Python process) stops `run` and `smoke` cleanly:
  finished_at is set, runs.interrupted = 1, the in-flight task is failed "interrupted" with no
  results row, the in-flight model call is logged with error "interrupted", exit 130 (Ctrl-C) or
  143 (SIGTERM). Later signals are ignored so they can't cancel the grader's container cleanup.
  Verified that uv forwards SIGTERM. Killing only a wrapping shell (TaskStop on a background shell) doesn't signal
  the run, so stop it with `pkill -TERM -f "[a]rena run --lineup"`.
- Anthropic think=false: Haiku 5.5 -> disabled, Sonnet 5.5 -> between_tools, Opus 5.5 can't
  (lineup load fails). With thinking on, the router asks for display "summarized", so
  calls.reasoning holds a readable summary for Anthropic models (the raw chain of thought is
  never returned). Ollama models store their full reasoning.
- Provider errors are not scored (no results row); the CLI reports them as "not scored".
- Replies cut off at max_tokens are flagged (calls.truncated) and get token-limit feedback.
- A deliberately adversarial solution could still fake pytest's summary line; the grader only
  guards against accidental early exits. test_solution.py is readable inside the sandbox.
- Docker Desktop 29.2.1 (WSL) sometimes misses a container's exit (~3% of back-to-back grades):
  pytest is done but docker reports "running" and `docker run` never returns. The grader checks
  container state after 5 s, kills a stalled container and re-grades (2 retries, then
  GraderError). This was the cause of the intermittent test_good_solution_passes failure.
- The VS Code Pylance "pydantic could not be resolved" warning means the interpreter isn't set to .venv/bin/python.
